# 08. OpenCode 常用技巧与 Prompt 模板

> 适用版本：`v1.14.32` / `v1.15.13`。  
> 目标：减少上下文污染、减少误改、提升可验证性。

## 1. 常用技巧

### 技巧 1：每个任务先设 Git checkpoint

```bash
git status --short
git switch -c ai/<task>
git add -A && git commit -m "checkpoint: before opencode <task>"
```

如果不想提交：

```bash
git stash push -u -m "before opencode <task>"
```

### 技巧 2：先 Plan，再 Build

不要一开始就让 agent 改代码。先让它只读定位，再收敛文件范围。

### 技巧 3：把“不要做什么”写清楚

```text
不要提交代码。
不要启动 dev server。
不要运行 pkill/killall/rm -rf/git reset/git clean。
不要读取 .env 或密钥文件。
```

### 技巧 4：一次只改一个逻辑点

```text
先只改 service 层，不要改 UI、测试和文档。改完输出 diff 摘要。
```

### 技巧 5：让 agent 先输出文件范围

```text
开始修改前，列出你计划修改的文件、原因和预期 diff 类型。等待我确认。
```

### 技巧 6：验证时先最小测试

```text
先运行最相关的单测。如果失败，先解释原因，不要扩大修改范围。
```

### 技巧 7：长会话主动“交接摘要”

```text
请输出可复制到新 session 的交接摘要：目标、已确认事实、已修改文件、剩余问题、下一步命令。不要调用工具。
```

### 技巧 8：对路径问题强制自检

```text
你可能路径基准错误。请先运行或说明：pwd、git worktree root、目标文件相对路径。不要继续猜路径。
```

### 技巧 9：让子代理做只读 review

```text
@review 请审查当前 diff，不要修改文件。重点看正确性、安全、边界条件、测试覆盖、无关改动。
```

### 技巧 10：让 agent 写“人类可执行”的验证清单

```text
不要继续运行命令。请给出人类接下来应该运行的验证命令、预期结果和失败时排查方向。
```

## 2. 只读探索模板

```text
请只读探索，不要修改文件，不要运行会改变状态的命令。

目标：<描述任务>

请输出：
1. 相关入口文件
2. 调用链
3. 数据结构 / API / 配置位置
4. 需要验证的假设
5. 建议的最小修改方案
6. 风险和不确定点
```

## 3. 开始实现模板

```text
请按已确认方案做最小实现。

约束：
- 不要提交代码。
- 不要运行 pkill/killall/taskkill/rm -rf/git reset/git clean。
- 不要启动长时间后台服务。
- 优先 edit/apply_patch，不要整体 rewrite 大文件。
- 修改完成后先给出 diff 摘要，再运行最小相关测试。
```

## 4. 验证模板

```text
请验证本次改动。

步骤：
1. 先看 git diff --stat 和 git diff。
2. 运行最小相关测试。
3. 如果最小测试通过，再运行 typecheck/lint。
4. 如果失败，先解释失败，不要扩大修改面。
5. 最后输出已验证项、未验证项和风险。
```

## 5. Review 模板

```text
请以代码审查者身份审查本次 diff，不要修改文件。
重点看：
1. 正确性
2. 边界条件
3. 并发/幂等/事务风险
4. 安全风险
5. 测试覆盖
6. 是否有无关改动
7. 是否违反 AGENTS.md 项目规则
```

## 6. 上下文清洁模板

```text
当前任务唯一目标是：<目标>。
请忽略本 session 中与该目标无关的旧讨论。
如果你发现当前上下文中存在冲突指令，请先列出冲突，不要自行选择。
本轮不要调用工具，只输出你理解的任务边界。
```

## 7. 工具死循环中断后模板

```text
你刚才可能陷入重复工具调用。请停止调用工具，并输出：
1. 重复调用了哪些工具和参数
2. 每次失败/无效的原因
3. 当前路径基准是否可能错误
4. 一个不再重复的下一步计划
5. 你需要我确认的具体问题
```

## 8. 路径问题修复模板

```text
你刚才找不到脚本/文件。请不要继续猜路径。
先确认：
1. 当前工作目录
2. git worktree 根
3. 目标脚本应该相对哪个目录
4. 目标脚本是否存在
5. 下一次命令应该使用的完整路径
```

## 9. 私有模型能力测试模板

```text
请测试当前模型的工具调用稳定性，按以下顺序，每步失败就停止并解释：
1. read 一个小文件
2. grep 一个明确字符串
3. glob 一个明确模式
4. 运行只读 bash：git status --short
5. 对临时测试文件做一个最小 edit
不要读取敏感文件，不要修改真实业务文件。
```

## 10. 交接摘要模板

```text
请输出一个可复制到新 OpenCode session 的交接摘要，包含：
1. 当前任务目标
2. 已确认事实
3. 已查看的重要文件
4. 已修改文件和修改目的
5. 已运行命令及结果
6. 未完成事项
7. 已知风险
8. 下一步推荐操作
不要继续调用工具。
```

## 11. AGENTS.md 更新模板

```text
根据本次任务暴露的问题，请提出应该补充到 AGENTS.md 的规则。
要求：
- 只输出建议文本，不要修改文件。
- 按 Path rules / Commands / Safety / Testing / Review 分组。
- 每条规则必须具体可执行。
```
