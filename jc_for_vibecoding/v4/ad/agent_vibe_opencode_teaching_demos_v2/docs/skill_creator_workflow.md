# Skill Creator + 人协同调试工作流

这个项目中的 Skill 目录是教学样例，重点不是一次写完，而是演示如何和 AI 协同沉淀业务上下文。

## 从 0 到 1 的建议步骤

1. 先收集 2-3 个真实任务样例。
2. 让 AI 归纳输入、输出、工具、风险和人工确认点。
3. 人确认任务边界，尤其是禁止动作和 Stop Rules。
4. 先写 `SKILL.md` 的最小版本：触发条件、流程、工具顺序、输出格式。
5. 把长文档、模板、schema、规则放进 `references/`。
6. 把确定性动作写成 `scripts/` 或封装为 `.opencode/tools/`。
7. 写一个 Command 作为高频入口。
8. 用 mock 数据跑通 happy path。
9. 加 validator，验证语法、schema、文件、参数边界。
10. 人工 review 逻辑是否正确，再迭代 Skill。

## 判断一个上下文是否应该沉淀

适合沉淀：

- 每周/每月重复发生；
- 有相对固定输入输出；
- 有历史文档、样例、脚本或模板；
- 有明确的安全边界；
- 可以构造 mock 数据验证。

不适合直接沉淀：

- 一次性探索；
- 会写生产数据；
- 需要大量主观裁决；
- 无法定义输入输出；
- 没有任何可验证样例。
