这个版本把原来的具体半导体业务 demo，改成了 **OpenCode 辅助编程与 context 工程教学包**。我仍然保留了你原始材料里的教学目标和部门场景启发，但把重点从“具体业务实现”转成了“如何沉淀稳定的 Agent 应用 context”。

我参考了 OpenCode 当前官方文档里的几个核心机制：项目规则用 `AGENTS.md` 承载，OpenCode 会把它作为项目自定义指令加载；Skill 放在 `.opencode/skills/<name>/SKILL.md`，通过 `name` 和 `description` 被发现并按需加载；Command 放在 `.opencode/commands/*.md`，可以用 `$ARGUMENTS` 作为用户输入入口；Custom Tool 用 TypeScript / JavaScript 定义，但工具内部可以调用 Python 等其他语言脚本；Permission 用 `allow / ask / deny` 控制 read、edit、bash、skill 等动作。([OpenCode][1])

我也把你给的 Agent 方法论融入了四个 demo：ReAct 的核心是 reasoning/action/observation 交错闭环，SWE-agent 的关键启发是软件工程 Agent 需要适合读仓库、改文件、跑测试的 Agent-Computer Interface；新版 demo 都围绕“先定义动作空间、再让 Agent 执行；先有验证闭环、再谈自动化”来组织。([arXiv.gg][2])

## 我对四个样例的重新设计

**Demo 00：规则驱动 dashboard 生成**

这是开场项目。用户只说一句话，比如：

```text
/dashboard 当前培训总时长 60 分钟。Demo 0 已完成，Demo 1 进行中，Demo 2 和 Demo 3 未开始。用户刚问：如何把一个临时 prompt 沉淀成稳定 Agent 应用？请生成讲师 dashboard。
```

Agent 应该根据 `AGENTS.md`、`dashboard-generator` Skill、模板说明和脚本，生成稳定的 HTML 看板，而不是临时手写一段 HTML。这个 demo 用来讲：OpenCode 工作流、context 分层、Command 入口、Skill 流程、脚本执行和验证闭环。

**Demo 01：Doc Spec 迁移开发**

这个 demo 对应你说的“基于历史文档和样例的开发，不同平台同一文档的可移植性实现”。为了教学通用性，我改成 Python 规则模块迁移到 JS/TS 风格模块。它的 context 包含：

```text
docs/order_discount_spec.md
docs/porting_spec_py_to_js.md
references/source/python_order_rules.py
references/examples/js_reference_style.mjs
tests/golden_cases.json
scripts/port_py_to_js.py
scripts/validate_port.py
```

重点不是“Python 转 JS”本身，而是让大家看到：迁移开发的稳定性来自功能 spec、迁移规范、历史样例、golden tests 和迁移报告，而不是让 Agent 凭空改代码。

**Demo 02：PDF / 论文复现项目**

这个 demo 对应你说的“从 PDF 中提取验证和测试实现模式，再结合环境包重新编写适配”。我放了一个 synthetic paper PDF 和 fallback text，脚本先抽取 `evidence.json`，再结合 `env_pkg/chip_eval_env.py` 生成最小复现项目。

它适合讲：

```text
PDF 不是直接变代码
PDF -> evidence -> design brief -> generated project -> validation manifest -> human review
```

这个 demo 也强调：Agent 可以读文档、提取信息、写代码、跑测试，但测试通过只能说明样例语法和行为通过，不能证明论文逻辑完全正确。

**Demo 03：权限约束与沙箱变更**

这个 demo 专门讲“动作空间设计”。里面有：

```text
protected/prod_config.json
protected/customer_data.csv
workspace/sandbox_config.json
policy/allowed_flags.json
scripts/propose_config_patch.py
scripts/apply_patch_to_sandbox.py
scripts/validate_config_patch.py
opencode.json
```

Agent 不能直接改 protected 配置，也不能读取 customer data；它只能通过封装脚本生成 proposal、应用到 sandbox、写 audit log、验证 protected 文件 hash 没变。这个 demo 最适合讲权限不是文档提醒，而是 runtime 约束和脚本/API 约束一起兜底。
