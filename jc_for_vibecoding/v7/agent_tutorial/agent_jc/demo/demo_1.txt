第1个样例 :
涉及doc spec开发规范
(基于历史代码、功能文档、样例和前端风格规范的迁移开发，不同 Web App 框架下同一功能场景的可移植性实现。
具体场景：已有一个 Gradio Web App，用于用户上传 CSV table 后进行数据分析和绘图；用户要求迁移成 Flask 实现，并保持相同功能场景和相同前端界面风格。
输入是原始项目实现代码、用户语句里体现的迁移要求、功能文档、前端风格规范和样例 CSV 验收项；输出是 Flask 项目实现代码。
背后构建好的 context 应该包含 Gradio->Flask 迁移规范、不同组件映射注意点、前端风格规范、测试项和人工 review 点。)

第1个样例延申对应的业务场景：
依据机台manual完成程序的转平台，
具体一点就是我们有A机台的测试程序(包括C++和机台pattern语言)，A机台的
manual, B机台的manual，希望基于上面三个材料生成适用于B机台的测试程序,机台
manual里会提供机台函数及其解释。
