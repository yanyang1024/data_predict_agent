# 动作空间设计

## 这个 demo 的动作空间

允许动作：

- 读取 `policy/allowed_flags.json` 和 `schemas/config_patch_schema.json`。
- 读取 `policy/data_access_policy.json` 和 `schemas/lot_query_schema.json`。
- 读取 `workspace/sandbox_config.json` 作为 sandbox 输入。
- 调用 `scripts/propose_config_patch.py` 生成 proposal。
- 调用 `scripts/apply_patch_to_sandbox.py` 生成 sandbox 变更结果。
- 调用 `scripts/validate_config_patch.py` 生成验证 manifest。
- 调用 `scripts/query_lot_history_service.py` 获取 lot history 聚合摘要和 SVG 图。
- 调用 `scripts/validate_data_service.py` 验证字段白名单、审计日志和 protected hash。

禁止动作：

- 读取 `protected/customer_data.csv`。
- 读取 `protected/lot_history_raw.csv`。
- 修改 `protected/prod_config.json`。
- 直接编辑 `workspace/sandbox_config.json`。
- 修改 policy 或 schema 来绕过限制。
- 把 production 作为自动应用目标。
- 导出原始行、客户字段、operator、tool owner 等不在白名单的字段。

## 教学讲法

这个 demo 要强调：权限配置只是兜底，真正可靠的 Agent 应用还需要把“可以做什么”封装成更小的 API 或脚本。Agent 负责理解需求、取证、选择动作和报告；脚本或 Data Service 负责执行受控动作；验证脚本负责检查边界没有被突破。

真实业务里，`query_lot_history_service.py` 可以替换成带鉴权、审计、限流和字段脱敏的 HTTP Data Service。教学包用本地 Python 脚本模拟这个边界，是为了减少依赖并方便课堂运行。
