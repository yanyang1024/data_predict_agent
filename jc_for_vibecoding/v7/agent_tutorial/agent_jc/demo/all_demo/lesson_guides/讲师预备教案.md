# 讲师预备教案

## 适用场景

这份教案用于讲师在正式授课前熟悉 demo、预演教学流程和检查运行环境。课程面向传统软件开发人员和数据分析工程师，重点不是展示“模型一次性写完代码”，而是展示如何用 OpenCode 把业务场景沉淀成可复用的 Agent context。

## 课程目标

学员听完后应理解四件事：

1. Agent 不是单个 prompt，而是带状态的决策循环。
2. 业务场景要先拆成规则、Skill、Command、Tool、脚本、权限和验证闭环。
3. Agent 应先取证、验证、纠偏，再自动完成任务。
4. 生产可用的 Agent 应用必须有动作空间、数据边界、审计产物和人工 review 点。

## 课前环境检查

在 `agent_jc/demo/all_demo` 目录执行：

```bash
python3 run_all_demos.py
```

期望看到：

```text
Golden cases passed: 5
Reproduction project validation passed.
Config patch validation passed.
Data service validation passed.
Context validation passed for 4 demos.
All demos completed successfully.
```

如果只想快速检查结构：

```bash
python3 scripts/validate_opencode_context.py
```

如果现场机器没有 Node.js，Demo 01 的 golden cases 会失败；讲师应提前安装 Node.js，或把 Demo 01 改成展示脚本和预生成产物，不现场运行验证。

## 预演顺序

建议正式授课前至少完整预演一次：

1. 打开根目录 `README.md`，确认能用 2 分钟讲清课程主线。
2. 打开 `lesson_guides/context分层速查表.md`，确认能解释 context 分层。
3. 逐个运行四个 demo 的 `python3 run_demo.py`。
4. 每个 demo 至少打开一次 `AGENTS.md`、Skill、Command、Tool、脚本和 output manifest。
5. 最后运行 `python3 run_all_demos.py`。

## 总体教学节奏

| 时间 | 内容 | 讲师目标 |
|---:|---|---|
| 0-5 min | 心智模型 | 建立“Agent = 决策循环，不是补全工具” |

| 8-20 min | Demo 00 | 从一句话到规则化 dashboard |

## Demo 00 预备要点

一句话场景：讲师只说当前培训进展，Agent 生成 HTML dashboard、状态报告和 manifest。

课前要打开：

- `00_rule_dashboard_agent/README.md`
- `00_rule_dashboard_agent/AGENTS.md`
- `.opencode/skills/dashboard-generator/SKILL.md`
- `.opencode/commands/dashboard.md`
- `.opencode/tools/dashboard.ts`
- `scripts/generate_dashboard.py`
- `scripts/validate_dashboard.py`

现场命令：

```bash
cd 00_rule_dashboard_agent
python3 run_demo.py
```

重点讲法：

- 如果每次让模型临时写 HTML，格式和字段会漂移。
- 把字段抽取规则、模板、脚本和验证固定下来，用户的一句话才会变成稳定产物。
- `output/dashboard_manifest.json` 是可交接的观察结果，不只是“页面生成成功”。

人工 review 点：

- 用户自然语言里缺失的字段是否用了默认值。
- Dashboard 内容是否代表真实教学状态。

## Demo 01 预备要点

一句话场景：把 Python 订单折扣规则迁移成 JS 模块，并跑 golden tests。

课前要打开：

- `01_doc_spec_portability/docs/order_discount_spec.md`
- `01_doc_spec_portability/docs/porting_spec_py_to_js.md`
- `references/source/python_order_rules.py`
- `references/examples/js_reference_style.mjs`
- `tests/golden_cases.json`
- `scripts/port_py_to_js.py`
- `scripts/validate_port.py`

现场命令：

```bash
cd 01_doc_spec_portability
python3 run_demo.py
```

重点讲法：

- 迁移不是“翻译语法”，而是“功能 spec + 源实现 + 目标风格 + golden cases”的组合。
- 当前 golden cases 覆盖 3 条正常路径和 2 条错误路径。
- 自动验证通过只证明样例行为一致，不证明金额精度策略生产可用。

人工 review 点：

- 金额计算用 Number 是否可接受。
- Coupon 优先级是否符合真实业务规则。
- 错误路径是否覆盖足够。

## Demo 02 预备要点

一句话场景：从 synthetic paper PDF 抽取实验逻辑，结合本地环境包生成最小复现项目。

课前要打开：

- `02_pdf_reproduction_agent/references/pdf_extraction_rules.md`
- `papers/synthetic_agent_eval_paper_text.md`
- `env_pkg/chip_eval_env.py`
- `scripts/extract_pdf_evidence.py`
- `scripts/build_repro_project.py`
- `scripts/validate_repro_project.py`
- `repro_project/README.md`

现场命令：

```bash
cd 02_pdf_reproduction_agent
python3 run_demo.py
```

重点讲法：

- PDF 不是直接“读完就写代码”，要先抽取 evidence。
- Evidence 进入设计摘要，再生成代码，再验证。
- 验证脚本只证明语法和样例测试通过，不能声称复现了论文全部结论。

人工 review 点：

- PDF 抽取是否遗漏公式上下文。
- 样例 anomaly index 是否符合论文意图。
- 算法是否适合真实数据。

## Demo 03 预备要点

一句话场景 A：打开 sandbox 配置 flag，但不改 production 配置。

一句话场景 B：查询 lot history 的 QTime / UT 汇总，但不读取 protected 原始数据。

课前要打开：

- `03_permission_sandbox_agent/README.md`
- `03_permission_sandbox_agent/opencode.json`
- `policy/allowed_flags.json`
- `policy/data_access_policy.json`
- `schemas/config_patch_schema.json`
- `schemas/lot_query_schema.json`
- `scripts/propose_config_patch.py`
- `scripts/query_lot_history_service.py`
- `scripts/validate_data_service.py`

现场命令：

```bash
cd 03_permission_sandbox_agent
python3 run_demo.py
```

重点讲法：

- Skill 里的“不要做”是软约束，`opencode.json` 和脚本/API 才是运行时边界。
- Agent 不能直接读 `protected/customer_data.csv` 或 `protected/lot_history_raw.csv`。
- Data Service 只返回聚合字段和图，不返回原始行。
- `validate_data_service.py` 检查字段白名单、lot 白名单、审计日志和 protected hash。

人工 review 点：

- QTime / UT 口径是否符合业务定义。
- 真实落地时脚本应替换成带鉴权、审计、限流和脱敏的 HTTP Data Service。

## 现场文件打开建议

为了节省时间，每个 demo 只打开 4 类文件：

1. `README.md`：业务场景和教学定位。
2. `AGENTS.md` 或 Skill：长期规则和任务 SOP。
3. `scripts/*.py` 或 `.opencode/tools/*.ts`：受控动作空间。
4. `output/*manifest.json` 或 report：验证和交接产物。

不要现场逐行解释所有代码。讲师只需要指出“这类上下文应该放在哪里、为什么要这样分层、验证证明了什么、没有证明什么”。

## 常见问题与回答

Q：这些 demo 是不是太简单？

A：简单是刻意设计的。教学目标不是复现复杂业务，而是给学员一个可复制的 context 工程骨架。真实业务可以替换掉模板、policy、Data Service 和验证脚本。

Q：为什么不用一个大 prompt 解决？

A：大 prompt 可以完成一次任务，但很难复用、审计和验证。Agent 应用要沉淀成规则、Skill、脚本、权限和 manifest。

Q：验证通过是否代表可以上生产？

A：不代表。验证脚本只证明结构、语法、样例行为或安全边界。业务逻辑、合规审批、数据口径仍需要人工 review。

Q：为什么 Demo 03 不让 Agent 直接读数据？

A：真实业务里数据库和客户数据是高风险资源。Agent 应通过 Data Service 获取脱敏、聚合、可审计的结果，而不是直接访问原始表。
