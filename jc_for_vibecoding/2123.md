这个 v0 Skill 的定位

它面向半导体 PETE / 产品与测试工程的 成品测试 C/C++ 代码迁移与重构，重点不是普通代码清理，而是受控迁移：

从 flow.c、efa、pattern、参数表、C/C++ 实现中提取必须保留的测试项；
基于白名单判断测试项、函数、变量、类、宏、参数是否保留；
删除“不在白名单且不支撑白名单测试项”的冗余代码；
结合目标产品生成或更新测试参数；
结合目标机台 / tester language pattern 做重构；
每次删除和修改都保留 before / after 证据，方便人工 trace；
对重要节点强制提醒人工 review。

OpenCode 现在支持通过 SKILL.md 定义 reusable behavior，并且会按需通过原生 skill tool 加载技能内容；项目级技能可放在 .opencode/skills/<name>/SKILL.md，也支持全局目录和 .agents/.claude 兼容路径。

已结合的 Context

我把场景拆成了 4 类上下文，已经写进 Skill：

软件工程 context
仓库结构、build system、compile flags、C/C++ 符号、宏、类、调用图、反向调用图、generated code、版本控制、diff、验证命令。
半导体产品测试 context
产品族、DUT / revision、测试项白名单、limits、units、bins、datalog name、site、pin、pattern、handler/prober、calibration、产品参数来源。
机台 / tester-platform context
目标机台语言 pattern、API wrapper、flow 文件、pattern 文件、setup / measure / bin / cleanup 顺序、多 site、资源锁、平台 hook、vendor/generated file。
治理与 trace context
白名单来源、删除策略、人工审批点、before/after manifest、change log、review checklist、rollback 策略。
已构建的 Workflow

Skill 里已经定义了这些工作流：

建立 migration case
创建迁移 case folder，保存 source/target product、source/target tester、entry files、whitelist、parameter source、before manifest。
提取并锁定测试项
从 flow.c、efa、pattern、参数表、C/C++ 实现中抽取 test item map，并区分 keep / delete_candidate / parameter_update / needs_review。
建立符号归属与可达性分析
不依赖简单 grep 删除，而是要求 forward graph + reverse graph，覆盖函数、变量、类、宏、helper、shared setup/cleanup。
分批删除冗余代码
只删除满足“非白名单、非白名单支撑代码、所有 caller/user 均属于删除集合、非平台 hook/generated/export/callback”的代码。每批都要记录证据并验证。
按目标机台 pattern 重构
把源机台 idiom 映射到目标 tester language pattern，保留 setup / measure / bin / datalog / cleanup 语义。
更新产品参数
把代码迁移和产品参数迁移分开处理，记录 old/new value、unit、precision、bin、datalog name、source of truth。
生成 traceable before/after evidence
输出 change log、review checklist、before/after manifest、diff summary、release readiness summary。
人工 review gate
对 shared helper、class、callback、exported API、macro、generated file、limit/bin/unit/datalog 变化强制人工确认。

OpenCode 也支持 AGENTS.md 作为项目级规则文件，适合把 build/test 命令、repo 结构、generated-code 边界和团队约定写进去；官方文档建议提交项目 AGENTS.md，让 OpenCode 理解项目结构和 coding patterns。

OpenCode 的 Plan agent 适合做代码分析、建议修改和制定计划，默认会限制写文件和 bash 命令，因此这个 Skill 建议先在 Plan mode 做测试项提取和删除候选分析，再切到 Build mode 做小批量已批准修改。

后续怎么迭代这个 Skill

第一版因为没有真实代码和数据，所以我把它设计成“方法论 + 审计框架 + 可扩展脚手架”。后续建议按这个顺序优化：

加入真实 flow.c / efa / pattern 片段，完善测试项提取规则；
固化你们实际的 whitelist 格式，比如 CSV、Excel export、YAML、spec database；
增加目标机台 tester language pattern reference，例如 references/tester-patterns-<machine>.md；
把“漏删的函数、变量、类”做成 fixtures，用于测试 reverse-call / symbol ownership 规则；
增加确定性脚本，例如基于 compile_commands.json、ctags、cscope、clangd、tree-sitter 的 C/C++ symbol indexer；
用真实迁移 case 统计 false delete、missed delete、needs_review 命中率，再更新 Skill 的删除策略。

我已经在压缩包内把这些迭代说明写进了 references/iteration-guide.md。
